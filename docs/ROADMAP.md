# 后续开发路线图

按「对用户价值 / 实现风险」排序。0.1.0 已完成 P0 全部与 P1 的 NeoForge、
P2 的大部分、P3 全部、P4 全部（详见 README 与测试报告）。

## 0.2 — 补齐验证与体验

- [ ] **微软登录真实联调**：用受控测试账户跑通登录、刷新、过期处理；
      增加「设备码/回环重定向」两种更顺滑的登录方式（需自备 Azure 应用注册）。
- [ ] **Forge / Fabric / Quilt 端到端验证**：各挑一个代表性版本跑通安装 + 启动，
      纳入 `docs/TEST-REPORT.md`。
- [ ] **真实 PCL2 / HMCL 实例导入**：在干净虚拟机上安装这两个启动器后回归，
      补齐它们各自的每实例配置（PCL2 的 `PCL/Setup.ini`、HMCL 的实例配置）解析。
- [ ] 磁盘空间预检（安装前估算所需空间并提示）。
- [ ] 下载队列持久化：重启后恢复未完成任务列表（目前 `.part` 已可续传）。

## 0.3 — Mod 与整合包增强

- [ ] Mod 更新检查（Modrinth `version_file` 哈希反查 → 项目 → 新版本）。
- [ ] 依赖解析：安装时提示缺失的前置 Mod（Modrinth `dependencies` 已可读）。
- [ ] CurseForge 支持：等用户提供 API Key 后按官方条款接入（不做未授权抓取）。
- [ ] 整合包导出时可选「导出为 Modrinth 依赖清单」而非纯 overrides。

## 0.4 — Java 与运行时

- [ ] 下载并管理 Mojang 官方 Java 运行时（`java-runtime-*` 组件），
      在系统没有合适 Java 时自动补齐。
- [ ] Java 版本不匹配时的「一键切换」建议。
- [ ] 通过注册表补充 Java 搜索（当前扫描 `JAVA_HOME`、PATH、常见安装目录与自带 runtime 目录）。

## 0.5 — 稳定性与可维护性

- [ ] 崩溃分析规则外置为可更新的 JSON，便于跟进新崩溃模式。
- [ ] 结构化日志导出（一键打包日志 + 配置 + 系统信息为诊断压缩包）。
- [ ] 端到端 UI 自动化测试（当前 GUI 只做人工截图验证）。
- [ ] 增量集成测试：对 Mojang 接口做「契约测试」，在 CI 中检测上游格式变化。

## 长期

- [ ] 增量/差分下载（复用已有对象，减少重复下载）。
- [ ] 多语言支持（当前 UI 为中文，资源已集中在 XAML 字符串中，可抽到 .resx）。
- [ ] 若需要跨平台，基于 `Orion.Core`（纯 `net10.0`）编写 Avalonia 前端。
